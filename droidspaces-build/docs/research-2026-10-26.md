# socrates 内核与 Droidspaces 适配调研

调研日期：2026-10-26（北京时间）。网页和 GitHub 默认分支会变化，实际构建使用 `config/sources.lock.json` 固定的提交。

## 结论

**针对这台手机当前系统，首选 `LineageOS/android_kernel_xiaomi_sm8550` 的 `lineage-23.2`，提交 `093e3da978e7b954d041a261d40975957c7fe6f1`。** 它的版本、源码提交短哈希和实机内核完全对应；再以实机 `/proc/config.gz` 为配置基线，应用 Droidspaces 官方的 SYSVIPC padding 6/7/8 补丁，补齐 namespace、devtmpfs 和网络配置。

这比直接使用小米 2023 年出厂源码、另一台 SM8550 手机的预编译包、或功能繁多的通用 GKI 构建器更贴近本机现有驱动环境。相同 `5.15.211` 版本号本身不足以证明源码、配置、符号 CRC、结构体布局、CFI 和厂商模块匹配。

保留当前 SukiSU **LKM** root 方式。第一次构建不引入额外 SUSFS、KPM、调度器、ZRAM 压缩器或 BBR 补丁；这些不是 Droidspaces 运行要求，后续可在可运行基线上分别评估。

## 3. GKI / KMI 的边界

当前源码 `build.config.constants` 的 BRANCH 为 `android13-5.15`，`build.config.common` 的 KMI_GENERATION 为 8。这里的 android13 指内核/KMI 世代，并不要求手机 Android 用户空间也停留在 13。

因此，Android 16 的本机仍应围绕当前 **android13-5.15 系**评估，不能改用 `android16-6.12`、`android15-6.6` 或 `android14-6.1` 的成品来“匹配 Android 版本”。这些不是当前厂商模块的直接替代品。

Google 的 GKI 同 KMI 稳定承诺针对相应分支、受保护接口与规定配置；本机使用带高通/小米增补的设备树和模块。通用 GKI 只能作为候选，仍需确认设备依赖的接口和配置。参考 [Google GKI versioning](https://source.android.com/docs/core/architecture/kernel/gki-versioning)。

## 4. Droidspaces 要求与实机缺项

官方最新正式发布查询结果：**v7.0.0，2026-10-14 发布**，release commit `37e8b45…`。配置文档与补丁固定到调研时 `64d53d17e765dad3028171204220f4d1134c7e37`，避免日后 main 改动悄悄改变构建。

来源：[官方 GKI 配置文档](https://github.com/ravindu644/Droidspaces-OSS/blob/64d53d17e765dad3028171204220f4d1134c7e37/Documentation/Kernel-Configuration.md)、[运行检查实现](https://github.com/ravindu644/Droidspaces-OSS/blob/64d53d17e765dad3028171204220f4d1134c7e37/src/check.c)、[v7.0.0](https://github.com/ravindu644/Droidspaces-OSS/releases/tag/v7.0.0)。

| 功能 | 配置 / 当前状态 | 处理 |
|---|---|---|
| SysV IPC、POSIX 消息队列 | SYSVIPC=n、POSIX_MQUEUE=n | 配套 kABI 补丁后开启 |
| PID / IPC 隔离 | PID_NS=n，IPC_NS 受前置依赖影响不可用 | 开启 PID_NS、IPC_NS |
| 设备文件系统 | DEVTMPFS=n | 开启 DEVTMPFS |
| NAT 的地址类型匹配 | NETFILTER_XT_MATCH_ADDRTYPE=n | 开启 |
| mount、UTS、network namespace | NAMESPACES、UTS_NS、NET_NS 已有 | 保持 |
| seccomp、cgroups / cgroup v2、memory controller | 已有 | 保持，不改宿主 cgroup 布局 |
| bridge、veth、TUN、FUSE、loop、ext4、OverlayFS | 已有 | 保持 |
| USER_NS | 当前关闭；官方推荐用于 sandbox / Docker procfs 场景 | 开启 |
| IPv6 NAT、macvlan、UFW/Fail2ban、tmpfs ACL/xattr | 官方 GKI 推荐功能 | 按 `config/droidspaces.config` 增补 |
| CPU quota、PID 数上限 | CFS_BANDWIDTH=n、CGROUP_PIDS=n | 本轮保留关闭，见下文 |

**GKI 不能直接照抄 non-GKI 的完整“全绿”配置列表。** 官方将 GKI 单列，是因为打开某些选项会改变 task、scheduler 和 cgroup 结构体布局。

已用官方 v7.0.0 aarch64 二进制在实机执行 Requirements 检查：实际缺少的 MUST HAVE 为 **PID namespace 和 IPC namespace**；devtmpfs、user namespaces、macvlan、IPv6 NAT 等缺项与配置采集一致。原始输出见 `evidence/droidspaces-before.txt`。正式版该命令输出文本，不能直接把 main 分支的 `check --json` 行为套到这个 release。

还核查了所有请求符号在当前源码 Kconfig 中是否存在：官方文档中的 `NETFILTER_XT_TARGET_REJECT` 在本树未定义，实际 IPv4/IPv6 选项为 `IP_NF_TARGET_REJECT`、`IP6_NF_TARGET_REJECT`，两者在实机本来已经启用。项目配置已使用实际存在的符号。

### SYSVIPC 补丁为何选 padding 6/7/8

官方对 5.4–6.6 首选 `001.GKI-below-6.12-fix_sysvipc_kabi_6_7_8.patch`。本机源码中 `task_struct` 的 padding 1 已用于 `user_dumpable`，而 6、7、8 仍是保留项。使用 6/7/8 与实际源码相符；使用涉及 slot 1 的替代版需要重审。

补丁把 SYSVIPC 新成员放到原有 padding 中，并通过 ANDROID_KABI 宏维持 genksyms 看到的接口布局。5.10 及以下的另一份 POSIX_MQUEUE padding 补丁不适用于本次 5.15 构建。补丁原作者与 Signed-off-by 已保留。

### CPU quota 与 PID limit 的取舍

官方明确说明：在 GKI 上直接开启 CFS_BANDWIDTH、CGROUP_PIDS 会改变大量导出符号 CRC，目前没有相应通用 padding 补丁。需要重编全部相关驱动并同步更新 boot、vendor_boot、vendor_dlkm、system_dlkm，才能把它们作为另一条完整方案评估。

本次先获得能够与现有 401 个厂商模块共存的内核。Droidspaces 的 memory limit 使用现有 MEMCG；CPU/PID 两项限制可由应用按缺失功能处理。没有这两项不等于容器不能运行。

## 5. Root、存储与网络

1. **Root**：实机 `CONFIG_KSU` 不存在，`/proc/modules` 有 kernelsu；init_boot 中也找到了 kernelsu.ko，证实为 LKM 路径。因此本轮无需新增内置 KSU，也无需改变 init_boot。该 LKM 的 `__versions` 是空的，不能宣称已验证其导入 CRC；保留现有模式并在启动后确认 root 才是完整结论。
2. **存储**：`/data` 是 F2FS。Droidspaces 官方建议 Android 默认用 ext4 sparse image；Docker overlay2 和 volatile rootfs 不直接依赖 F2FS 目录作为底层。现有 loop/ext4/overlay 已满足相应内核基础。
3. **网络**：默认 NAT / gateway 模式适合容器独立网络栈。Docker 的桥接网络需要独立网络栈；官方示例要求 iptables-legacy。macvlan 面向有线 LAN，不应把它当成手机 Wi-Fi 上必然可用的二层直连方案。
4. **SELinux**：保持当前 Enforcing。按 Droidspaces 官方应用安装/重启流程加载所需规则，不把永久 Permissive 作为内核适配的默认条件。
5. **SUSFS**：本次不新增。若以后启用，需检查 mount 隐藏设置对容器可见性的影响；Fuxi 的直接适配先例明确提到全局隐藏 SUS mounts 会影响启动。

参考：[Android 安装](https://github.com/ravindu644/Droidspaces-OSS/blob/64d53d17e765dad3028171204220f4d1134c7e37/Documentation/Installation-Android.md)、[Docker 示例](https://github.com/ravindu644/Droidspaces-OSS/blob/64d53d17e765dad3028171204220f4d1134c7e37/Documentation/Cool-things-you-can-do.md)、[功能与存储说明](https://github.com/ravindu644/Droidspaces-OSS/blob/64d53d17e765dad3028171204220f4d1134c7e37/Documentation/Features.md)。

## 6. Windows + GitHub Actions 实现

本地不安装 WSL、Linux VM 或 Android 内核交叉编译环境。PowerShell 7、ADB、Git、gh 完成采集与触发；Linux runner 完成编译。

已实现的工作流：`.github/workflows/build-kernel.yml`。

| 阶段 | 具体行为 |
|---|---|
| 实机采集 | root ADB 读取 config、ROM 标识、模块；本地保存当前槽启动镜像。原始镜像和模块二进制不会进入 Git |
| 固定源码 | 拉取 Lineage commit `093e3da978e7…`，而非随默认分支漂移 |
| 固定编译器 | AOSP prebuilts commit `9916fb51…` 下的 clang-r563880c；验证子目录 Git tree ID |
| 配置 / 补丁 | SYSVIPC padding 6/7/8；编辑 gki_defconfig 与实机配置，再 olddefconfig 解析依赖 |
| 编译 | arm64 Image 与树内 modules；保持 Full LTO、CFI、MTE/KASAN、SCS、BTF、MODVERSIONS |
| 模块比较 | 读取手机 `.ko` 的 ELF `__versions`，逐个核对新 Module.symvers；缺少原内核导出项也视为失败 |
| 外部符号分类 | 用手机 kallsyms 区分内核导出和模块间导出，避免把 vendor-to-vendor 符号误报为内核缺失 |
| 封装 | 固定 AnyKernel3 commit `c0729818…`；仅替换当前槽 boot 内核，设备条件 socrates / Android 16 |
| 留存 | Image、ZIP、SHA256、完整配置、差异、Module.symvers、ABI 报告、源码补丁、版本清单与构建日志 |

保留 `5.15.211-g093e3da978e7` release 是为了现有模块的 vermagic 兼容；改动由 `build.json`、`source.patch` 和配置差异明确标识。**保留字符串本身不等于 ABI 兼容证明**，真正的导入 CRC 比较独立执行。

runner 依赖初始化还遇到了 Azure Ubuntu 镜像下载 48 MB 包却持续十余分钟的实际问题。`scripts/prepare-runner.sh` 已切换 Ubuntu 官方 HTTPS 源；并依据本树 `arch/arm64/kernel/vdso32/Makefile` 确认 32 位 vDSO 使用 Clang/LLD，移除了这条 LLVM 构建路径不使用的交叉 GCC 下载。该改动不关闭 COMPAT_VDSO。

私有仓库作为首轮默认，避免将实机输入直接公开。runner 的 Linux 工具安装、空间调整和 swap 只发生在 GitHub 的临时环境。首次执行已暴露具体的磁盘问题：源码、工具链 Git 对象和预先分配的 24 GiB swap 耗尽 runner 空间。已改为固定提交的源码归档及单个 Clang 目录归档，删除下载包后才按实际余量分配 swap，并给编译输出预留空间。源码归档按 SHA256 校验；Google Gitiles 工具链归档含生成时间，压缩包哈希随请求改变，因此改为校验解压内容的 Git tree ID（文件内容、路径、执行权限和符号链接）。本地与云端均已确认 tree `571ed3e20b5708cea1177d5072853fc5b85b6877`。后续执行已证实工具链重复下载耗时明显，因而增加仅针对固定编译器的缓存，缓存命中后仍重新校验 tree；不缓存整棵内核输出。

先建立当前 ROM 上可运行的 Droidspaces 基线，再研究同 5.15 系的安全更新。若升级到 5.15.220 或新 Lineage 版本，重新采集手机配置与模块，比较 source/KMI/CRC；不因版本数字更高便直接替换。

若明确需要 CPU quota / PID limit 或更深的容器功能，再建立包含内核、devicetrees、modules 和相应分区的整套构建。Lineage 已公开这些配套源码，但“源码公开”不自动证明所有实机预编译模块均可重建；应以模块清单逐项核对。
